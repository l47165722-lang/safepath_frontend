# Safe Path UI 변경 및 검증 보고서

2026-10-10 · 기준: 제공된 SRS의 4.1 사용자 인터페이스 · 기준 화면: 360 × 800dp

## 적용 범위

기존 앱 UI를 SRS의 화면 목록과 예시 배치에 맞게 변경했다. 카카오 지도 SDK와 Mapbox 경로 조회·선정 로직, 안전시설 원본 데이터, Google/Firebase 로그인 연동은 유지했다. 서버 API나 지도 제공자를 교체하지 않았다.

주요 색상은 네이비 `#1B4965`, 스카이블루 `#5FA8D3`로 통일했다. 위험 상태와 입력 오류에만 빨간색을 사용한다. 하단 탭은 **홈 / 친구 / 보호 중 / 내 정보** 4개다. 주요 버튼과 지도 조작 버튼은 최소 48dp 터치 영역을 확보했다.

기존 **안전지수 화면(SafetyMapScreen)**과 해당 탭은 제거했다. 기존 보호자 관리 화면은 친구 화면과 출발 준비 화면으로 정리했다. 임시 UI 검증용 Activity는 최종 소스/APK에서 제거했다.

## 기존 데이터·연동의 한계

- 현재 `local.properties`에는 `KAKAO_NATIVE_APP_KEY`, `KAKAO_REST_API_KEY`, `MAPBOX_ACCESS_TOKEN`이 설정되지 않았다. 검증 실행에서도 Mapbox 설정 오류 상태를 확인했다. 키 값을 추가하거나 변경하지 않았다. 실제 지도 타일·장소 검색·경로 성공 조회는 유효한 설정으로 추가 확인해야 한다.
- 기존 경로 모델에는 소요시간, 0~100 안전점수, CCTV/비상벨/지킴이집/경찰서 종류별 개수가 없다. 없는 값은 `—` 또는 미제공으로 표시한다. 기존 시설 밀도 지표를 별도로 표시하며 안전점수로 바꿔서 제시하지 않는다. 미제공 안전점수 막대는 채우지 않는다.
- 기존 친구·보호자 데이터는 기기에 저장된 연락처다. 회원 검색·요청/수락 API, 귀가 세션 생성·알림, 보호자의 실시간 세션 API는 기존 프로젝트에 연결되어 있지 않다. 관련 UI와 콜백을 마련했지만 실제 전송·세션 생성이 되었다고 표시하지 않는다. 보호 중 탭은 실제 제공된 세션이 없으면 빈 상태다.
- 비밀번호는 화면 입력 상태로만 사용하며 실제 귀가 세션으로 저장·전송하지 않는다. 기존 SOS는 공유 대상을 사용자가 고르는 Android 공유 화면을 사용한다.

## 검증

최종 명령: `gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --offline`

- 최종 결과: **BUILD SUCCESSFUL**.
- 단위 테스트: **8개 통과, 실패 0개**. 경로 선정·안전시설 테스트 포함.
- Lint: **오류 0개**, 경고 29개, 힌트 0개. 경고는 Gradle 의존성 표기/버전, KTX 사용 제안 및 Compose Modifier 인자 순서 제안이며 자세한 내용은 `app/build/reports/lint-results-debug.html`에 있다.
- `git diff --check`: 공백 오류 없음.
- `NavigationRepository`, `SafetyRepository`, `KakaoPlaceRepository`, Google 인증 코드, 앱 Gradle 설정, 워치 소스는 변경되지 않은 것을 diff로 확인.
- 최종 APK의 DEX에서 임시 `UiReviewActivity`가 없는 것을 확인.
- 작업 전 존재하던 `.idea/deploymentTargetSelector.xml` 수정은 유지했다.

에뮬레이터 Pixel_10_Pro를 720 × 1600px, 320dpi로 설정해 360 × 800dp 기준으로 확인했다. 사용자의 연결된 실제 휴대전화에는 설치하거나 데이터를 변경하지 않았다.

UI 입력 검증 결과:

1. 가입 필수 정보가 비어 있을 때 이름·전화번호 빨간 테두리와 오류 안내: 통과.
2. 빈 친구 검색 입력에서 필드 오류 안내: 통과.
3. 목적지 없이 경로 찾기를 누르면 목적지 오류 안내: 통과.
4. 보호자 1명 선택과 숫자 4자리 입력 후 시작 버튼 활성화: 통과.
5. 좌표가 있는 목적지에서 경로 비교 화면으로 전환: 통과. 경로 성공 결과는 키 미설정으로 검증하지 못했으며 설정 오류 UI를 확인.

로그인·가입·친구·경로 선택/추천·출발 준비·이동중/위험상황·내 정보·설정의 화면 배치와 스크롤, 고정 버튼을 스크린샷으로 확인했다. 카카오 지도 배경은 키 미설정으로 표시되지 않았으므로 지도 렌더링 성공을 주장하지 않는다.

**스크린샷의 친구 요청, 연락처와 보호 이동/위험 상태는 에뮬레이터 전용 예시 데이터다.** 경로 카드 예시는 기존 모델의 필드만 제공한 UI 검증 데이터다. 해당 데이터와 임시 검증 화면은 최종 앱에 포함되지 않는다. `routes-live.png`는 실제 화면 전환 후 키 미설정 오류를 표시한 기록이다.

## 최신 수정: 카카오 알림톡 자동 발송

- 사용자가 전화번호에 자동 발송하는 알림톡 방식을 선택했다. 친구 요청 전달 채널을 카카오 알림톡으로 전환하고 입력·전송 접수·알림 목록 안내 문구를 변경했다.
- 서버 생성 주소를 `/api/requests/alimtalk`으로 변경했다. SOLAPI ATA 타입, 채널 ID, 승인 템플릿 ID 및 요청자명·요청 링크 변수를 사용하며 `disableSms: true`로 문자 대체 발송을 차단한다. 이전 SMS 어댑터와 생성 주소를 제거했다.
- 요청자 정보 확인, 전화번호 인증, 수락, 양방향 친구 저장은 유지했다. 전화번호 소유자 확인용 Firebase 인증 문자는 기존 수락 절차의 별도 기능이다.
- 로컬 검증: APK 빌드·단위 테스트·Lint 실행 성공. 앱 테스트 11개 및 서버 테스트 18개 통과, Lint 오류 0개·경고 42개. 알림톡 요청 형식·템플릿 변수·문자 대체 발송 차단·중복 방지·이전 문자 API 차단을 대역 테스트로 검증했다.
- 사용자가 카카오 채널·승인 템플릿이 아직 없음을 확인했다. 실제 발송과 Firebase 원격 배포는 미완료다. 채널 연동, 템플릿 승인, 서버 비밀키 설정 및 배포가 필요하며 [설정 안내](../../backend/README.md)에 템플릿 초안과 설정 구조를 정리했다.

## 최신 수정: 친구 추가·자동 문자 요청·웹 수락

- 친구 탭 우측 상단에 친구 추가 버튼을 넣었다. 전체 화면 입력에서 이름·전화번호를 입력하고 자동 문자 요청 API를 호출한다.
- Firebase ID 토큰 기반 서버를 `backend/`에 추가했다. 요청 저장, 7일 만료 링크, SOLAPI 자동 문자 전송 어댑터, 요청 조회·수락·거절·취소, 양쪽 친구 연결 해제를 구현했다. 비밀키는 앱에 포함하지 않는다.
- 웹 링크에서 요청자 이름·마스킹 연락처·만료일을 확인하고, Google 로그인 및 수신 번호 인증 후 수락할 수 있도록 작성했다. 수락은 서버에서 번호를 확인하고 양방향 친구 관계를 트랜잭션으로 저장한다.
- 기존 전체 화면 알림에 서버의 받은·보낸 요청을 연결했다. 수락된 친구는 기존 친구 목록과 보호자 선택에서 사용하며 계정별로 캐시한다. 활성 친구 화면에서는 15초마다 상태를 갱신한다.
- 최종 로컬 검증: APK 빌드 성공, Android 단위 테스트 11개 통과, 서버 HTTP/API 및 SMS 어댑터 테스트 16개 통과. Lint 오류 0개·경고 42개, JavaScript 구문 검사 및 공백 검증 통과.
- **활성화는 미완료:** 사용자에게 SMS 계정이 없음을 확인했다. 서버 비밀키·등록 발신 번호·Firebase 원격 배포·앱 서버 주소 연결이 남아 있다. 실제 문자 발송, 웹 전화번호 인증, 운영 Firestore, 실제 단말 간 연결은 검증하지 않았다. 서버가 없을 때 성공으로 표시하지 않는다. 설정은 [backend/README.md](../../backend/README.md)에 기록했다.

## 최신 수정: 친구 알림 전체 화면

- 친구 탭 알림을 전체 화면 Dialog로 변경했다. 하단 플로팅 탭바 위까지 전체 영역을 덮고 시스템 바 영역은 안전 여백을 적용한다.
- 상단 뒤로가기 버튼과 시스템 뒤로가기로 친구 목록에 복귀한다. 받은 요청·보낸 요청 목록 및 수락·거절·취소 동작을 유지했다.
- 검증: `:app:assembleDebug --offline` 성공, `git diff --check` 통과. 이번 수정의 실제 기기 조작 검증 및 화면 캡처는 수행하지 않았다.

## 최신 수정: 목적지 자동 조회·경로 스와이프

- 즐겨찾기는 집·학교·추가만 유지하고 아이콘, 은은한 배경, 둥근 버튼으로 정리했다. 외부 플로팅 패널의 라운드는 하단 탭바와 동일하다.
- 상단 안전 경로 찾기 버튼을 제거했다. 검색 결과·지도·즐겨찾기로 목적지를 확정하면 기존 경로 추천 영역이 자동으로 열린다. 출발지가 아직 없으면 출발지 선택을 안내하고, 현재 위치가 확보되면 자동 조회한다. 입력 중인 검색어만으로는 조회하지 않는다.
- 기존 카드 디자인을 유지하고 세 카드의 세로 목록을 HorizontalPager 한 장씩 좌우 스와이프 선택으로 변경했다. 선택한 페이지에 지도 경로, 출발 준비, 워치 경로 정보가 연결된다. 새 화면은 추가하지 않았다.
- 같은 즐겨찾기를 다시 선택해도 추천 영역이 열린다. 스와이프 중에는 출발 준비 버튼을 비활성화하여 이전 경로로 진행하는 것을 방지한다.
- 최종 검증: assembleDebug, testDebugUnitTest, lintDebug 성공. 기존 단위 테스트 8개 통과, Lint 오류 0개·경고 41개, git diff --check 통과. 경고는 의존성 버전·KTX·버전 카탈로그·modifier 순서 관련이다.
- 이번 변경은 빌드·단위 테스트·정적 검증까지 수행했다. 실제 기기에서 자동 조회 및 스와이프 조작 검증과 새 화면 캡처는 수행하지 않았다. 아래 스크린샷은 이전 UI의 기록이다.

## 후속 수정: 홈 화면 상·하단 디자인

- 상단을 기존 SafePath 로고, 출발지·목적지 가로 입력, 교환 버튼, 안전·최단·추천 탭 디자인으로 복원했다.
- 홈 하단 즐겨찾기 시트를 144dp 높이로 축소했다. 최근 목적지는 내부 스크롤로 확인하며 안전 경로 찾기 버튼은 하단에 고정한다.
- 검증: `:app:assembleDebug --offline` 성공, `git diff --check` 통과.
- 위 화면 기록은 후속 수정 전의 검증 이미지다. 이번 수정에서는 에뮬레이터 화면 캡처를 다시 수행하지 않았다.

## 후속 수정: 플로팅 탭바·즐겨찾기·친구 화면

- 하단 탭바를 좌우 16dp 여백, 24dp 코너 라운드, 그림자가 있는 플로팅 형태로 변경했다. 시스템 내비게이션 영역과 간격을 확보했다.
- 즐겨찾기는 집·학교·추가 버튼만 남기고 제목, 최근 목적지, 거리, 안내문, 경로 찾기 버튼을 제거했다. 높이는 72dp이며 탭바와 동일한 `FloatingPanelShape`를 사용한다.
- 경로 찾기 버튼은 홈 상단 카드로 옮겨 경로 추천 화면으로 이동하는 기능을 유지했다.
- 친구는 프로필 썸네일·이름·관계·마스킹 전화번호로 구성한 목록으로 변경했다. 저장된 친구를 이름순으로 표시한다.
- 상단 입력은 기존 친구 목록의 이름·전화번호·관계 검색으로 변경했고, 요청 버튼은 검색 버튼으로 바꿨다. 전화번호의 하이픈·공백을 제외한 숫자 검색, 키보드 검색, 검색 초기화도 지원한다.
- 받은 요청과 보낸 요청은 우측 상단 알림 버튼에서 여는 알림 목록으로 이동했다. 요청 수 배지, 수락·거절·취소 UI와 기존 콜백을 유지한다.
- 검증: APK 빌드 성공, 기존 단위 테스트 8개 통과, Lint 오류 0개·경고 28개, 공백 검증 통과. 이번 수정의 에뮬레이터 화면 캡처는 수행하지 않았다. 앞의 이미지들은 이전 버전의 기록이다.
