# PR #13 병합 충돌 및 웨어 점검 — 2026-10-11

## GitHub와 병합

최신 main `7f5747e`에는 PR #12의 워치 센서 수집과 폰 릴레이 서비스가 포함되어 있었습니다. PR #13은 해당 변경과 충돌했고, 로컬에는 충돌 파일을 스테이징했지만 병합 커밋을 마치지 않은 상태가 있었습니다.

## 웨어 점검 및 보완

- 폰과 워치의 applicationId가 일치하고, 빌드된 debug APK의 서명 인증서도 일치합니다.
- 폰→워치 경로 상태 경로는 `/safepath/status`, 워치→폰 센서 경로는 `/safepath/motion`입니다. 서비스 필터와 송수신 필드 이름이 일치합니다.
- 두 센서 중 하나가 아직 준비되지 않았을 때 다른 센서 값을 0으로 채운 데이터를 전송하던 문제를 수정했습니다.
- 가속도계와 자이로스코프가 각각 이벤트를 발생시키며 합쳐진 데이터가 목표 빈도의 두 배까지 나갈 수 있어, 센서의 단조 증가 타임스탬프로 최대 20Hz를 적용했습니다. 재시작 시 이전 센서 값과 송신 상태를 초기화하고 유효하지 않은 값은 제외합니다.
- StateFlow와 단일 DataItem은 최신 값을 동기화합니다. 모든 센서 샘플을 손실 없이 전달하는 스트림은 아니며, AI 분석용 연속 샘플이 필요하면 별도 버퍼링·전송 설계가 필요합니다.
- 폰 릴레이 서비스는 현재 센서 값을 로그로 확인하는 단계입니다. AI 서버 요청·응답 및 위험 판단은 구현되지 않았습니다.
- 워치 수집은 WearApp이 composition에 있는 동안 수행하며 종료 시 해제합니다. 별도의 장시간 백그라운드 수집 서비스는 없습니다.
